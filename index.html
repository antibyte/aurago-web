Schnellstart

In Sekunden startklar

Wähle deinen Weg: signierter Installer, Docker Compose oder aus dem Quellcode.

terminal 
# Signierter Installer (empfohlen) – prüft Release-Signatur und alle Dateien
curl -fsSLO https://github.com/antibyte/AuraGo/releases/latest/download/install.sh
bash install.sh

# Oder: Quick Install direkt vom main-Branch
curl -fsSL https://raw.githubusercontent.com/antibyte/AuraGo/main/install.sh | bash

# Der Installer startet AuraGo und zeigt URL + Erst-Passwort.
# Meist: http://localhost:8088
terminal 
git clone https://github.com/antibyte/AuraGo.git
cd AuraGo
docker compose up -d

# Persistente Volumes + eingeschränkter Docker-Socket-Proxy
# Öffne http://localhost:8088
terminal 
# Benötigt Go 1.27.3+ und Node.js
git clone https://github.com/antibyte/AuraGo.git
cd AuraGo
node scripts/build-ui-bundles.js
go run ./cmd/assetpack -out deploy -stage assets/web
go build -trimpath -ldflags="-s -w $(cat deploy/web-assets.ldflags)" -o aurago ./cmd/aurago
./aurago --check-assets

FAQ

Häufige Fragen

AuraGo ist ein selbst gehosteter AI Agent für Home Labs. Er läuft als Single Binary mit zero Dependencies auf jedem Linux-Server oder Raspberry Pi. Er hat direkten Zugriff auf deine Infrastruktur, hält alle Daten lokal und arbeitet 24/7 für dich, on demand oder automatisiert.

Ja. AuraGo unterstützt Ollama out of the box für lokale Modelle wie Qwen, Llama, Mistral oder Gemma. Du kannst auch jede OpenAI-kompatible API oder OpenRouter nutzen.

AuraGo ist unter aktiver Entwicklung – ein Maintainer, gelegentlich raue Kanten und Breaking Changes. Linux steht an erster Stelle; Windows- und macOS-Builds sind weniger getestet.

AuraGo wurde Security-First entwickelt: AES-256-GCM Vault für API-Keys, bcrypt + TOTP 2FA, Sandbox für Python-Execution, HTTPS mit Auto-TLS, LLM Guardian für Tool-Call-Scanning und granularer Danger Zone mit individuellen Toggles.

Schau auf GitHub vorbei. Issues, PRs und Diskussionen sind willkommen. Das Projekt ist ein One-Man-Projekt. Jede Hilfe zählt.

Deine Daten liegen bei deiner Installation. Gehostete Modelle und externe Dienste erhalten aber die Eingaben ihrer Anfragen – self-hosted heißt nicht automatisch offline. Mit lokalen Modellen über Ollama bleibt alles im Haus.
